### Operator decisions recorded (2026-11-07)
1. **LLM policy.** Upstream's `docs/development/README.md` says: "PRs generated by LLMs will not be accepted and we require disclosure of any LLM usage." They closed PR #191 on those grounds. We therefore **ask first in an issue**: we disclose AI assistance and open PRs only if the maintainers accept that.
2. **Rebase-merge-only upstream vs our no-rebase / no-force rule.** Each PR revision gets a **new branch** (`upstream/<topic>-vN`), cut from fresh matterbridge-org/master and rebuilt with `cherry-pick -x`. No rebase or force-push anywhere.
3. **Fork `master`.** **Force-move it once** from c4157a4d to matterbridge-org/master ef72d19f, under the operator's explicit authorization. After that it only moves by fast-forward.

### Facts the plan relies on (verified by the research workflow wf_87e6e4da-527)
- **Cross-fork PRs work.** matterbridge-org is a fork of 42wim, so it shares our network root. `gh pr create -R matterbridge-org/matterbridge --head datacosmos-br:<branch>` is valid; selfhoster1312 and kousu already land PRs this way.
- **Branch base.** PR branches must be cut from matterbridge-org/master, because its history was rewritten and bf39c654 is the vendor-free equivalent of c4157a4d.
- **Upstream gates:**
  - `go fmt ./...` followed by `git diff --exit-code`
  - `golangci-lint` v2.12 with `--build-tags=goolm`, run against both `.golangci.yaml` (new issues) and `.golangci-incremental.yaml`
  - `go test -tags goolm ./...` on 1.26.x and stable
  - `CGO_ENABLED=0 go build -tags goolm`
- **Upstream PR conventions:** a changelog entry under `# unreleased` linking the PR, docs/protocols/<proto> updates, and titles shaped `<area>: <summary>`.
- **Upstream has no vendor/.** It requires go 1.26 and the module path `github.com/matterbridge-org/matterbridge`. It also no longer ships the harmony, keybase or steam bridges.
- **Our fork is admin-controlled and unprotected.** Actions are disabled. Dependabot PR #2 is stale. These branches are fully absorbed (0 unique commits): `mspgeek`, `snapshot/detached-20260727-56e7bd01ca09`, `wip/session-suspend-20260824/aihub-audit`.
- **No auto-push daemon was found.** The run of "fixes" pushes came from interactive or agent sessions, so the legacy freeze must be protected by a ruleset.
